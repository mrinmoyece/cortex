# Testing Guide

## Test Strategy

Cortex uses a layered test strategy. Tests at each layer have different scope, speed, and external dependencies.

```
                    ┌─────────────────────┐
                    │   Eval Regression   │  Ragas / LLM-judge suite — run on demand, not a CI gate
                    ├─────────────────────┤
                    │  Integration Tests  │  Full graph runs with a mocked router and faked stores
                    ├─────────────────────┤
                    │     Unit Tests      │  Fast, isolated, all external calls mocked
                    └─────────────────────┘
```

**Coverage target:** 80% minimum, enforced in `pyproject.toml`.

**The suite needs no services.** Redis is faked, Qdrant and every HTTP client
are mocked, and no test makes a network call. `pytest` runs on a clean laptop
with nothing installed but the dev extra. `tests/eval/` holds regression
*fixtures* for the evaluation harness, not tests — pytest does not collect it.

## Running Tests

```bash
# Install dev dependencies
pip install -e ".[dev]"

# Full suite with coverage
pytest

# By module
pytest tests/test_agents/     # Agent tests
pytest tests/test_rag/        # RAG pipeline tests
pytest tests/test_mcp/        # MCP server and tools
pytest tests/test_safety/     # Safety middleware
pytest tests/test_api/        # FastAPI endpoints

# Single test
pytest tests/test_agents/test_agents.py::TestPlannerAgent::test_plan_returns_tasks -v

# With coverage report
pytest --cov=src/cortex --cov-report=html
open htmlcov/index.html
```

## Test Modules

### `tests/test_agents/`
Tests for PlannerAgent, ExecutorAgent, CriticAgent, and the Task state model.

All LLM calls are mocked via `mock_router` fixture. Tests validate:
- Correct parsing of LLM responses
- Graceful handling of malformed JSON
- Error propagation through the graph
- Critique context injection during replanning

### `tests/test_rag/`
Tests for SemanticChunker, SparseRetriever, RRF fusion, and Document model.

No external service dependencies — all tests run in-process.

Key cases:
- Chunking respects paragraph boundaries
- BM25 correctly ranks semantically relevant docs above irrelevant ones
- RRF boosts documents appearing in both dense and sparse results
- Duplicate deduplication in fused results

### `tests/test_mcp/`
Tests for all MCP tool functions and the MCPClient.

`execute_code` tests run actual subprocess executions, so they exercise the
real code path rather than a mock. They enable the tool explicitly through the
`code_execution_enabled` fixture, because it is **off by default** and is not
a sandbox — see [LIMITATIONS.md](LIMITATIONS.md). There is also a test
asserting it stays off without that fixture: a security default that nothing
checks is a security default one careless refactor away from flipping.
`search_knowledge` mocks the RAG pipeline.

### `tests/test_safety/`
Tests for InjectionDetector, PIIScanner, and SafetyMiddleware.

Pattern matching tests are deterministic — no LLM needed.

### `tests/test_api/`
Integration tests for FastAPI endpoints using `httpx.AsyncClient`.

The app is tested against a real FastAPI instance with:
- Real JWT tokens (generated by `create_access_token`)
- Mocked background tasks (runs don't actually execute)
- Mocked `ingest_document` for ingestion tests

### `tests/eval/`
Ragas regression suite. Requires LLM API keys — excluded from the default CI run if keys not present.

## Mocking Strategy

Cortex uses three categories of mocks:

**1. LLM Router mock** (`mock_router` fixture)
```python
# Returns a configurable mock response
mock_router.complete.return_value = mock_llm_response('{"tasks": [...]}')
```

**2. MCP Client mock** (`mock_mcp_client` fixture)
```python
mock_mcp_client.call_tool.return_value = {"result": "mock result"}
```

**3. External stores** (Qdrant, Redis)  
Patched with `unittest.mock.AsyncMock` in tests that would hit real infrastructure. Integration tests can use real stores if `docker compose up` is running.

## Adding Tests for New Features

1. Create `tests/test_<module>/test_<feature>.py`
2. Use `@pytest.mark.asyncio` for all async tests
3. Use fixtures from `conftest.py` for shared state
4. Mock external calls — tests must not require internet or running services
5. Aim for: happy path + at least 2 error paths per public method

Example:
```python
class TestMyNewAgent:
    
    @pytest.mark.asyncio
    async def test_happy_path(self, base_state, mock_router):
        mock_router.complete.return_value.choices[0].message.content = '{"result": "ok"}'
        agent = MyNewAgent()
        with patch("cortex.agents.my_agent.get_router", return_value=mock_router):
            result = await agent.run(base_state)
        assert result is not None
    
    @pytest.mark.asyncio
    async def test_handles_llm_failure(self, base_state, mock_router):
        mock_router.complete.side_effect = LLMProviderUnavailableError("all failed")
        agent = MyNewAgent()
        with patch("cortex.agents.my_agent.get_router", return_value=mock_router):
            with pytest.raises(AgentError):
                await agent.run(base_state)
```

## CI Configuration

```yaml
# .github/workflows/test.yml
- name: Test
  run: pytest --cov=src/cortex --cov-fail-under=80
  env:
    SECRET_KEY: test-secret-key-32-characters-min
    # Do NOT add real LLM API keys here — eval tests are skipped without them
```
